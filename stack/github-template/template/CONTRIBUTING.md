# Contributing to {{ORG_NAME}}

Thanks for wanting to help. The flow is the same in every repo:

1. **Issue first.** Open an issue (bug, feature or chore form) before writing code,
   unless it is a typo-level fix. Say what you want to change and why.
2. **Branch.** Name it `<type>/<short-topic>`, for example `fix/login-redirect` or
   `docs/install-steps`. Types: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`.
3. **Commit.** Use [Conventional Commits](https://www.conventionalcommits.org/):
   `feat(scope): what changed`. Small commits, each one buildable.
4. **Pull request.** Fill in the template, link the issue with `Closes #123`, and keep
   the PR focused on one thing.
5. **Review.** CI must be green. A maintainer reviews; please answer comments with a
   change or a reason.

## Ground rules

- No secrets, tokens, client names or personal data in code, issues or commit messages.
- Docs change in the same PR as the behaviour they describe.
- Be kind: see the [code of conduct](CODE_OF_CONDUCT.md).

## Labels

Priority: `p0` (now), `p1` (next), `p2` (later). Type: `bug`, `enhancement`,
`documentation`, `chore`. Newcomer-friendly work carries `good first issue`.
